# SafeLoop 产品需求说明（第一版规划）

## 1. 项目背景
SafeLoop 旨在帮助制造企业、研发中心和实验室把设备点检与隐患闭环管理从纸质检查表或通用 Excel 表格中转移到统一系统中。项目面向仍然依赖人工记录、人工汇总和人工追踪的场景，目标是把设备台账、点检任务、点检记录、异常、隐患、整改记录、复查记录和闭环管理串联起来，形成清晰可追溯的业务流程。

本项目仅用于学习、展示和面试汇报，所有数据均为虚构测试数据，不使用任何真实企业内部信息。

## 2. 目标用户
- EHS 管理人员：负责统一管理点检任务、异常确认、隐患分派、整改复查和数据看板。
- 检查人员：负责按要求完成设备点检，提交点检记录并上报异常。
- 设备责任人：负责关注自己管辖设备的整改进展，并提交整改记录。
- 系统管理员：负责账号、角色和系统基础配置维护。

## 3. 当前业务痛点
- 纸质检查表或 Excel 记录难以形成统一的设备点检档案。
- 点检结果容易遗漏、重复录入，统计汇总依赖人工。
- 异常发现后，是否进入正式隐患闭环缺少统一规则，整改和复查往往分散在多个渠道。
- 超期点检和超期整改难以及时提醒，管理层难以及时掌握风险状态。
- 设备台账和历史记录分散，无法快速定位某台设备的检查和整改情况。

## 4. 项目目标
- 建立设备基础台账与一物一码基础信息管理。
- 支持设备点检任务生成、执行和记录提交。
- 支持异常提交、异常确认、隐患形成、整改和复查闭环。
- 支持超期提醒与角色受限的数据看板展示。
- 形成适合作品集展示和面试追问的完整业务流程。

## 5. 统一术语
1. 点检任务：系统要求在指定期限内完成的一次设备检查。
2. 点检记录：检查人员实际提交的检查结果。
3. 异常：点检中发现的偏离正常状态的现场现象。
4. 隐患：经 EHS 管理员审核确认，需要进入正式整改闭环的问题。
5. 整改记录：设备责任人提交的一次整改措施和证据。
6. 复查记录：EHS 管理员对整改结果作出的确认记录。
7. 关闭：复查通过后，隐患完成闭环。

## 6. 项目范围
### 6.1 第一版包含的业务
- 设备基础台账管理
- 设备一物一码信息管理
- 点检任务生成与执行
- 点检记录提交
- 异常提交与异常确认
- 隐患形成、分派、整改、复查与关闭
- 超期提醒与统计看板
- 角色权限控制

### 6.2 第一版暂不包含的业务
- 与 ERP / MES / CMMS 的深度系统集成
- AI 自动判断风险等级、自动生成整改建议
- 复杂审批流、多层级审批链
- 真实生产现场设备实时监测数据接入
- 供应链、采购、物资领用等非点检管理流程

## 7. 暂不开发的功能
- 生成正式法律或法规依据的合规报告
- 基于大模型的风险智能判断与自动建议
- 高度定制化的流程引擎
- 多语言、多组织架构的企业级权限体系
- 复杂的移动端离线同步能力

## 8. 业务规则与流程
### 8.1 异常与隐患流程
- 检查人员和设备责任人只能提交异常，不能直接创建正式隐患。
- 异常状态流转为：草稿 → 待确认 → 已确认隐患 / 一般异常 / 已驳回。
- 只有 EHS 管理员可以将异常确认为隐患，并确定风险等级、整改责任人和整改期限。
- 设备责任人不能自行关闭隐患。

### 8.2 隐患主流程
- 隐患主状态采用单一主流程：待分派 → 待整改 → 整改中 → 待复查 → 已关闭。
- 复查不通过时进入已驳回整改，并重新返回待整改。
- 已撤销状态保留，但必须记录撤销原因和操作人。
- 设备责任人提交整改后，隐患直接进入待复查；只有 EHS 管理员复查通过后才能关闭。

### 8.3 整改与复查记录
- 整改记录和复查记录作为隐患下的过程记录，不再设计独立且复杂的主状态机。
- 整改记录保存整改说明、措施、附件、提交人和提交时间。
- 复查记录保存通过/不通过、复查意见、附件、复查人和复查时间。

### 8.4 逾期规则
- “已逾期”不作为检查任务或整改任务的独立主状态，而是根据截止时间计算出的时间标记。
- 检查任务主状态为：待执行、执行中、已提交、已完成、已取消。
- 检查任务时间标记为：正常、即将到期、已逾期、补录。
- 整改任务同样将逾期作为标记处理。
- 检查任务按任务截止时间判断逾期，整改按整改期限判断逾期。
- 提前提醒默认 3 天，后续可配置。

### 8.5 配置规则
- 设备类别设置默认点检模板和默认周期，单台设备可以覆盖默认设置。
- 复查只允许 EHS 管理员完成。
- 检查人员只能查看本人任务、本人记录及当前设备必要的历史异常。
- 看板根据角色限制数据范围。
- EHS 管理员原则上不代替检查人员录入；特殊补录必须记录代录人、实际检查人、实际检查时间和补录时间。

## 9. 项目验收标准
项目第一版可视为基本达标，当满足以下条件时即可进行演示：
- 能完成设备台账录入与一物一码信息展示。
- 能完成一次完整的点检任务执行流程。
- 能从异常提交走到异常确认、隐患形成、整改、复查和关闭。
- 不同角色能够看到并执行符合其权限范围的内容。
- 能通过看板直观看到待办、超期、已关闭和风险分布情况。
- 系统界面可用于演示，流程逻辑清晰，能接受面试追问。
