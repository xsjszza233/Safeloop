# SafeLoop 状态流转设计

## 1. 统一术语
- 点检任务：系统要求在指定期限内完成的一次设备检查。
- 点检记录：检查人员实际提交的检查结果。
- 异常：点检中发现的偏离正常状态的现场现象。
- 隐患：经 EHS 管理员审核确认，需要进入正式整改闭环的问题。
- 整改记录：设备责任人提交的一次整改措施和证据。
- 复查记录：EHS 管理员对整改结果作出的确认记录。
- 关闭：复查通过后，隐患完成闭环。

## 2. 检查任务状态
检查任务表示某一台设备在某一时间段内需要完成的点检工作。

| 主状态 | 含义 | 可转移到 | 触发角色 | 禁止的跳转 |
|---|---|---|---|---|
| 待执行 | 任务已生成，尚未开始 | 执行中、已取消 | EHS 管理员/系统自动 | 不能直接跳到已提交或已完成 |
| 执行中 | 检查人员已开始执行 | 已提交、已取消 | 检查人员 | 不能直接回到待执行 |
| 已提交 | 检查人员已提交点检记录 | 已完成 | 检查人员 | 不能再次回到执行中 |
| 已完成 | 任务已形成完整记录并进入后续处理 | 无 | 系统自动/检查人员 | 不能回退 |
| 已取消 | 任务被取消 | 无 | EHS 管理员/系统管理员 | 不能再恢复为执行态 |

| 时间标记 | 说明 | 触发方式 |
|---|---|---|
| 正常 | 未接近截止时间 | 系统计算 |
| 即将到期 | 临近截止时间 | 系统计算 |
| 已逾期 | 超过截止时间 | 系统计算 |
| 补录 | 由补录行为生成的记录 | EHS 管理员/系统管理员 |

## 3. 异常状态
异常用于记录检查中发现的现场现象，不能直接形成正式隐患。

| 状态 | 含义 | 可转移到 | 触发角色 | 禁止的跳转 |
|---|---|---|---|---|
| 草稿 | 异常内容已填写但尚未提交 | 待确认 | 检查人员/设备责任人 | 不能直接进入隐患闭环 |
| 待确认 | 异常已提交，等待 EHS 确认 | 已确认隐患、一般异常、已驳回 | EHS 管理员 | 不能直接进入已关闭 |
| 已确认隐患 | EHS 确认该异常进入正式隐患闭环 | 待分派 | EHS 管理员 | 不能直接跳回草稿 |
| 一般异常 | EHS 确认该异常不需要进入正式隐患闭环 | 无 | EHS 管理员 | 不能转为隐患 |
| 已驳回 | EHS 认为该异常不符合进入隐患流程的条件 | 无 | EHS 管理员 | 不能再恢复为隐患 |

## 4. 隐患状态
隐患采用单一主流程，作为正式整改闭环的核心对象。

| 主状态 | 含义 | 可转移到 | 触发角色 | 禁止的跳转 |
|---|---|---|---|---|
| 待分派 | 异常已确认为隐患，等待 EHS 分派 | 待整改 | EHS 管理员 | 不能直接进入待复查 |
| 待整改 | 隐患已分派，等待责任人开始整改 | 整改中、已撤销 | EHS 管理员 | 不能直接进入已关闭 |
| 整改中 | 设备责任人正在执行整改 | 待复查、已撤销 | 设备责任人 | 不能直接进入已关闭 |
| 待复查 | 责任人已提交整改记录，等待 EHS 复查 | 已关闭、已驳回整改 | EHS 管理员 | 不能直接回到待分派 |
| 已关闭 | 复查通过后，隐患完成闭环 | 无 | EHS 管理员 | 不能由设备责任人自行关闭 |
| 已撤销 | 隐患被取消，必须记录撤销原因和操作人 | 无 | EHS 管理员/系统管理员 | 不能再恢复 |
| 已驳回整改 | 复查不通过，需要重新整改 | 待整改 | EHS 管理员 | 不能直接进入已关闭 |

## 5. 整改记录与复查记录
整改记录与复查记录不是独立主状态机，而是隐患下的过程记录。

### 5.1 整改记录
- 保存整改说明、措施、附件、提交人和提交时间。
- 设备责任人提交后，隐患自动进入待复查。
- 设备责任人不能修改原始检查记录、降低风险等级、删除记录或自行关闭隐患。

### 5.2 复查记录
- 保存通过/不通过、复查意见、附件、复查人和复查时间。
- 复查只允许 EHS 管理员完成。
- 复查不通过时，隐患进入已驳回整改，并重新返回待整改。

## 6. 逾期逻辑
- “已逾期”仅作为时间标记，不是独立主状态。
- 检查任务按任务截止时间判断逾期。
- 整改按整改期限判断逾期。
- 提前提醒默认 3 天，后续可配置。

## 7. 配置规则
- 设备类别设置默认点检模板和默认周期，单台设备可以覆盖默认设置。
- 检查人员只能查看本人任务、本人记录及当前设备必要的历史异常。
- 看板根据角色限制数据范围。
- EHS 管理员原则上不代替检查人员录入；特殊补录必须记录代录人、实际检查人、实际检查时间和补录时间。

## 8. 设计说明
- 该版本先采用“异常先入库、隐患再进入整改闭环”的规则，避免把所有问题都直接视为正式隐患。
- 复查通过后才进入关闭，确保闭环完整。
- 状态流转尽量保持清晰，避免复杂回退和重复审批。

## 9. 待确认事项
- 特殊补录是否需要额外审批，还是仅记录补录信息即可？
- 设备类别默认点检模板与默认周期的配置入口是否开放给 EHS 管理员或仅由系统管理员维护？
