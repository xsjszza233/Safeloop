# SafeLoop 点检管理模块设计（第一版）

## 1. 模块目标

点检管理模块承接设备台账，并把设备的周期性检查、现场记录、异常上报和后续隐患整改串联起来。模块面向制造企业、研发中心和实验室的日常 EHS 管理场景，第一版解决以下问题：

- 根据设备类别默认配置或单台设备覆盖配置，按周期形成点检计划和点检任务；
- 让点检执行人员按统一模板完成现场检查，保存每个检查项目的结果；
- 将现场发现的问题记录为异常，保留发现人、设备、检查项目和现场描述等上下文；
- 由 EHS 管理员判断异常是否形成隐患，并在确认后进入分派、整改、复查和关闭流程；
- 在设备详情中形成可追溯的点检、异常、隐患和整改记录链路。

本模块只定义内部 EHS 管理流程，不生成法规结论，也不把设备风险等级、异常建议等级和隐患风险等级混为一类。

## 2. 核心概念与边界

| 概念 | 定义 | 边界 |
| --- | --- | --- |
| 点检模板 | 针对某类设备定义的一组检查项目和填写规则 | 模板是可复用配置，不代表某次实际检查。 |
| 点检计划 | 描述某台设备按什么周期、模板和人员规则持续生成任务 | 计划是调度规则，不保存现场结果。 |
| 点检任务 | 某台设备在一个计划时间窗口内需要执行的一次检查 | 任务是一条待办实例，时间标记不属于主状态。 |
| 点检记录 | 点检执行人员针对某个任务提交的实际检查事实 | 原始提交后原则上不可覆盖修改；补录和更正应留痕。 |
| 异常 | 现场发现的偏离正常状态的现象 | 异常不等于隐患，不能直接进入整改关闭流程。 |
| 隐患 | EHS 管理员确认需要正式整改闭环的问题 | 隐患必须关联确认来源、风险等级、责任人和整改期限。 |
| 整改记录 | 设备责任人针对隐患提交的措施和证据 | 提交整改不等于关闭隐患。 |
| 复查记录 | EHS 管理员对整改结果作出的通过或不通过结论 | 只有复查通过后隐患才能关闭。 |

## 3. 完整业务流程

```text
设备
  ↓
点检模板
  ↓
点检计划
  ↓
点检任务
  ↓
现场执行
  ↓
点检记录
  ↓
异常发现
  ↓
EHS 确认
  ↓
隐患形成
  ↓
整改关闭
```

### 3.1 各步骤的责任、输入和输出

| 步骤 | 主要责任人 | 输入数据 | 输出数据 |
| --- | --- | --- | --- |
| 设备 | EHS 管理员维护业务配置；系统管理员维护技术与权限配置 | 设备编号、类别、状态、风险等级、责任人、实际点检周期、关联模板 | 可参与点检的设备主数据及设备级点检配置 |
| 点检模板 | EHS 管理员 | 适用设备类别、检查周期、检查项目、判断标准和填写要求 | 启用的点检模板及模板版本 |
| 点检计划 | EHS 管理员；后续可由系统按设备配置初始化 | 在用设备、实际周期、关联模板、计划起始日期、执行人员或分配规则 | 有效点检计划、下一计划日期 |
| 点检任务 | 系统按计划生成；EHS 管理员可发起临时任务 | 设备、模板版本、计划日期、截止时间、执行人员 | 一条可执行的点检任务及其时间标记 |
| 现场执行 | 点检执行人员 | 点检任务、模板检查项目、设备必要历史信息 | 每项检查结果、备注、异常描述和模拟附件信息 |
| 点检记录 | 点检执行人员提交；系统归档 | 任务信息、检查人员、检查时间、检查明细和总体结果 | 不可被无痕覆盖的点检记录；任务进入已提交并完成归档 |
| 异常发现 | 点检执行人员；设备责任人也可独立上报设备异常 | 关联设备、来源点检记录或检查明细、异常描述、现场证据、建议等级 | 状态为待确认的异常记录 |
| EHS 确认 | EHS 管理员 | 异常记录、设备上下文、现场补充说明 | 已确认隐患、一般异常或已驳回的审核结论 |
| 隐患形成 | EHS 管理员 | 已确认异常、隐患风险等级和确认意见 | 状态为待分派的隐患记录；完成责任人和期限分派后进入待整改 |
| 整改关闭 | 设备责任人整改；EHS 管理员复查 | 整改措施、整改证据、复查意见和复查结果 | 整改记录、复查记录；复查通过后隐患关闭 |

### 3.2 设备状态对任务生成的影响

- 在用设备按实际点检周期持续生成常规点检任务。
- 停用或维修中设备暂停生成新的常规点检任务，也暂停新增逾期判断；历史任务和历史逾期记录保留。
- 报废设备不再生成点检任务，也不再计算逾期。
- 设备状态变化时，未完成任务不得自动删除。EHS 管理员应选择保留、取消或转为专项点检，并记录操作日志。
- 停用或维修中设备恢复在用后，默认从恢复日期重新计算下一次点检日期；EHS 管理员可选择立即生成恢复后点检任务。

## 4. 点检模板设计

### 4.1 模板基础字段

| 字段 | 建议类型 | 业务含义 |
| --- | --- | --- |
| 模板 ID | UUID | 数据库内部唯一标识，用于关联计划、任务和版本。 |
| 模板编号 | 文本，唯一 | 业务可识别编号，例如 `TPL-FH-001`。 |
| 模板名称 | 文本 | 模板的业务名称。 |
| 适用设备类别 | 设备类别关联 | 限定模板可关联的设备类别。第一版一个模板只适用一个设备类别。 |
| 风险等级 | 低/中/高，可多选 | 表示模板适用的设备风险等级范围，不是异常建议等级或隐患风险等级。 |
| 检查周期 | 周期值 | 类别默认周期，例如每周、每月；单台设备可覆盖实际周期。 |
| 模板版本 | 正整数 | 记录模板发布版本，保证历史任务仍能还原当时的检查内容。 |
| 模板状态 | 草稿/启用/停用 | 只有启用版本可用于生成新任务；停用不影响历史记录。 |
| 创建人 | 用户关联 | 创建模板的 EHS 管理员。 |
| 创建时间 | 日期时间 | 模板首次创建时间。 |
| 更新时间 | 日期时间 | 模板最近一次更新或发布的时间。 |

模板发布后如需修改检查项目，应生成新版本或保存任务生成时的模板快照，不能让历史点检记录随模板修改而变化。

### 4.2 检查项目字段

| 字段 | 建议类型 | 业务含义 |
| --- | --- | --- |
| 检查项目 ID | UUID | 检查项目内部唯一标识。 |
| 检查项目名称 | 文本 | 简短描述需要检查的对象。 |
| 检查内容 | 文本 | 说明检查范围和关注点。 |
| 检查方法 | 文本 | 说明现场如何完成检查，例如目视、查看仪表或试运行。 |
| 判断标准 | 文本 | 用于帮助执行人员选择正常或异常的内部判断描述，不引用未确认法规。 |
| 是否必须填写备注 | 布尔值 | 为真时，该项目没有备注不能提交。第一版也可配置为“结果异常时必填”。 |
| 是否需要上传照片 | 布尔值 | 表示业务是否要求照片；第一版仅展示模拟附件信息，不实现真实上传。 |
| 排序号 | 正整数 | 控制检查项目在移动点检页面中的显示顺序。 |
| 是否启用 | 布尔值 | 控制新任务是否包含该项目，不删除历史项目结果。 |

第一版每个检查项目的结果只使用“正常”和“异常”。任何项目选择“异常”时，必须填写异常描述；是否要求照片由检查项目配置决定。

## 5. 点检计划设计

点检计划用于把设备级点检配置转换为可重复执行的任务生成规则。

| 字段 | 业务含义 |
| --- | --- |
| 计划编号 | 计划业务编号。 |
| 关联设备 | 计划对应的单台设备。 |
| 关联模板及版本 | 生成任务时使用的模板。 |
| 计划类型 | 常规点检或临时点检。 |
| 实际检查周期 | 继承类别默认周期或设备级覆盖周期。 |
| 生效日期 | 计划开始参与任务生成的日期。 |
| 下次计划日期 | 下一次应生成任务的目标日期。 |
| 执行人员/分配规则 | 指定人员，或由 EHS 管理员生成任务时分配。第一版优先采用指定人员。 |
| 计划状态 | 启用、暂停、结束。设备停用、维修中或报废时按设备状态规则处理。 |
| 创建人、创建时间、更新时间 | 计划配置的审计信息。 |

同一设备第一版只保留一条有效的常规点检计划，但可以同时存在临时点检任务。周期或模板变更只影响以后生成的任务，不修改已生成任务。

## 6. 点检任务设计

### 6.1 任务字段

| 字段 | 业务含义 |
| --- | --- |
| 任务编号 | 一次点检任务的业务编号。 |
| 关联设备 | 指向被检查设备，并保留必要设备信息快照。 |
| 关联模板 | 指向生成任务时使用的模板版本或模板快照。 |
| 关联计划 | 常规任务关联点检计划；临时任务可以为空。 |
| 任务类型 | 常规点检、临时点检、维修后专项点检或补录。 |
| 计划日期 | 计划执行日期。 |
| 截止时间 | 用于计算正常、即将到期和已逾期时间标记。 |
| 执行人员 | 被分配的点检执行人员。 |
| 任务状态 | 待执行、执行中、已提交、已完成、已取消。 |
| 时间标记 | 正常、即将到期、已逾期或补录；它不是主状态。 |
| 开始时间、提交时间、完成时间 | 任务关键节点时间。 |
| 创建来源 | 周期计划、EHS 临时发起、维修后专项或特殊补录。 |

### 6.2 状态转换逻辑

SafeLoop 已有状态文档将点检任务主状态统一定义为：

```text
待执行 → 执行中 → 已提交 → 已完成
   └──────────────→ 已取消
```

| 当前状态 | 触发动作 | 下一状态 | 触发角色/方式 |
| --- | --- | --- | --- |
| 待执行 | 开始点检 | 执行中 | 被分配的点检执行人员 |
| 待执行 | 取消任务 | 已取消 | EHS 管理员；必须记录原因 |
| 执行中 | 提交完整检查结果 | 已提交 | 点检执行人员 |
| 执行中 | 取消任务 | 已取消 | EHS 管理员；必须记录原因 |
| 已提交 | 系统校验并完成记录归档 | 已完成 | 系统自动；补录场景由 EHS 管理员确认 |
| 已完成 | 无 | 终态 | 不允许回退或覆盖原始记录 |
| 已取消 | 无 | 终态 | 不允许恢复为执行态，可重新创建任务 |

需求中建议的“异常待处理”和“已关闭”不作为点检任务主状态，处理方式如下：

- “异常待处理”是业务视图标记：点检任务已经完成，但其关联异常仍处于待确认或后续处理中。
- “已关闭”用于隐患复查通过后的终态，不用于点检任务。点检任务本身以“已完成”为终态。
- 这样可以避免点检任务因异常或整改进展反复改变主状态，同时仍能在列表中提示后续事项。

### 6.3 时间标记

- 正常：尚未进入提前提醒窗口。
- 即将到期：距截止时间不超过默认 3 天；未来可配置。
- 已逾期：超过截止时间且任务仍未完成或取消。
- 补录：由特殊补录产生，仅标识记录来源，不等同于逾期。

## 7. 现场执行与点检记录

### 7.1 现场执行规则

- 只有被分配的点检执行人员可以开始并提交任务；EHS 管理员原则上不代替执行人员录入。
- 页面按模板排序展示所有启用检查项目，每项必须选择“正常”或“异常”。
- 任一项目为异常时，任务总体检查结果为“异常”，并必须填写异常描述。
- 模板配置为必须备注或需要照片的项目，提交前应进行完整性校验。第一版照片只使用模拟附件。
- 点检提交与异常提交可以在一次操作中完成，但必须分别形成点检记录和异常记录。
- 网络中断、离线缓存和并发编辑不在第一版范围内。

### 7.2 点检记录字段

| 字段 | 业务含义 |
| --- | --- |
| 记录编号 | 点检记录业务编号。 |
| 任务编号 | 关联唯一点检任务。第一版一个已完成任务对应一条正式点检记录。 |
| 关联设备 | 冗余关联设备，便于设备历史查询和权限控制。 |
| 模板版本/快照 | 保存提交时实际执行的检查内容。 |
| 检查人员 | 实际完成现场检查的人员。 |
| 检查时间 | 现场实际检查时间，不等同于系统提交时间。 |
| 提交时间 | 记录进入系统的时间。 |
| 检查结果 | 正常或异常。 |
| 检查明细 | 每个检查项目的结果、备注和附件引用。 |
| 异常描述 | 总体异常补充说明；结果正常时可为空。 |
| 图片附件 | 模拟附件列表；未来保存 Supabase Storage 路径和元数据。 |
| 备注 | 本次点检的其他补充说明。 |
| 是否补录 | 标识是否为特殊补录。 |
| 代录人 | 补录时记录实际操作系统的 EHS 管理员。 |

### 7.3 检查明细字段

每条点检记录包含多条检查明细，每条至少保存：检查项目 ID、项目名称快照、检查内容快照、判断标准快照、结果、备注、附件引用和排序号。这样即使模板以后修改，历史记录仍可正确还原。

## 8. 异常与隐患关系

### 8.1 核心原则

```text
现场人员发现异常
  ↓
提交异常（待确认）
  ↓
EHS 管理员审核
  ├─ 确认形成隐患 → 分派 → 整改 → 复查 → 关闭
  ├─ 判定为一般异常 → 异常流程结束
  └─ 驳回 → 记录理由后结束
```

异常是现场事实或现象，隐患是 EHS 管理员审核后进入正式整改闭环的业务对象。两者必须使用不同编号、状态和风险字段。

### 8.2 谁可以提交异常

- 点检执行人员可以在执行任务时提交与检查项目关联的异常。
- 设备责任人可以针对本人负责设备独立提交异常，但不能直接创建隐患。
- EHS 管理员可以提交日常巡查发现的异常，也可以进行特殊补录，但必须保留实际发现人和补录信息。
- 系统管理员不承担日常异常上报和业务审核职责。

### 8.3 谁可以确认隐患

只有 EHS 管理员可以把待确认异常判定为隐患，并确定隐患风险等级、整改责任人和整改期限。系统管理员只维护技术与权限配置，不代替 EHS 管理员完成业务确认。

### 8.4 异常如何结束

- 草稿由提交人完成后进入待确认。
- EHS 管理员确认需要整改闭环时，异常进入“已确认隐患”，同时创建关联隐患记录。
- EHS 管理员确认无需进入正式隐患闭环时，异常进入“一般异常”，并记录审核说明。
- 内容无效、重复或不符合受理条件时进入“已驳回”，并记录驳回原因。
- “已确认隐患”“一般异常”和“已驳回”均为异常流程终态。异常不使用“已关闭”来代替这些审核结果。

### 8.5 隐患如何进入整改流程

1. EHS 管理员确认异常形成隐患，保存来源异常、隐患风险等级和确认意见。
2. 隐患进入待分派，EHS 管理员设置整改责任人和整改期限后进入待整改。
3. 设备责任人开始整改，隐患进入整改中，并提交整改记录和模拟证据。
4. 提交整改后进入待复查，由 EHS 管理员创建复查记录。
5. 复查通过后进入已关闭；复查不通过进入已驳回整改，再返回待整改。
6. 隐患如需撤销，必须由 EHS 管理员或系统管理员操作，并记录撤销原因和操作人。

第一版一条异常最多形成一条隐患；一个隐患可以有多次整改记录和多次复查记录，以支持复查不通过后的重新整改。

## 9. 权限设计

“点检执行人员”与现有角色文档中的“检查人员”是同一业务角色，后续页面统一使用“点检执行人员”作为模块内称呼。

| 角色 | 可以查看 | 可以修改 | 可以执行 |
| --- | --- | --- | --- |
| 系统管理员 | 全部模板、计划、任务及记录；用于系统维护和问题排查 | 用户、角色、技术参数和权限配置；不修改原始点检事实 | 管理账号与权限；不执行日常点检，不确认隐患，不关闭隐患 |
| EHS 管理员 | 全部设备点检配置、任务、记录、异常、隐患和整改进展 | 点检模板、设备类别默认周期、设备级点检配置、计划、任务分配；可按规则补录但必须留痕 | 生成或取消任务、发起临时点检、审核异常、确认隐患、分派整改、复查和关闭隐患 |
| 设备责任人 | 本人负责设备的基础信息、点检历史、相关异常、隐患和整改进度 | 不能修改原始点检记录；可以补充本人提交的异常草稿和整改记录 | 独立提交设备异常、执行整改、提交整改记录；不能确认或关闭隐患 |
| 点检执行人员 | 本人点检任务、本人点检记录、任务设备必要信息及必要历史异常 | 执行中任务的检查结果、明细、备注和异常草稿；提交后不能无痕修改 | 开始任务、提交点检记录、提交异常；不能确定隐患风险等级、整改人或期限 |

### 9.1 数据权限原则

- EHS 管理员按当前组织管理范围查看业务数据；第一版演示可使用单组织全量数据。
- 点检执行人员只能操作分配给本人的待执行或执行中任务。
- 设备责任人只能查看和处理本人负责设备的数据。
- 历史点检记录、异常审核结论、整改记录和复查记录不得物理删除；第一版仅提供只读追溯。
- 前端隐藏按钮不能替代后端权限校验。接入 Supabase 后必须使用服务端校验和行级安全策略约束数据范围。

## 10. 第一版范围控制

### 10.1 第一版实现

- 使用本地虚构数据展示通风橱、配电箱和消防器材等模拟点检模板；
- 使用本地虚构数据展示周期任务、临时任务和不同时间标记；
- 提供适配手机、平板和电脑的点检执行页面；
- 支持填写正常/异常结果、检查明细、备注和模拟附件信息；
- 支持在前端演示点检记录保存和任务状态变化；
- 支持从异常提交到 EHS 确认、隐患形成和整改关闭的界面流程演示。

当前“点检记录保存”仅指第一版前端模拟保存，不承诺刷新后持久保留，也不代表已接入数据库。

### 10.2 第一版暂不实现

- IoT 设备自动采集；
- 图片 AI 识别或自动风险判断；
- 电子签名；
- 真实短信、邮件、企业微信等消息推送；
- Supabase 或其他数据库同步；
- 真实图片上传与对象存储；
- 复杂排班、自动轮班和多人会签；
- 移动端离线同步；
- ERP、MES、CMMS 或法定检验系统集成。

## 11. 未来数据库核心实体

### 11.1 实体清单

| 实体 | 主要职责 | 关键关联 |
| --- | --- | --- |
| `equipment` | 保存设备主数据及设备级点检配置 | 关联设备类别、责任人；拥有多个计划、任务和记录 |
| `inspection_template` | 保存模板基础信息、适用类别、版本和状态 | 拥有多个检查项目；被计划和任务引用 |
| `inspection_item` | 保存模板中的检查项目和填写规则 | 属于一个模板版本 |
| `inspection_plan` | 保存设备的周期性任务生成规则 | 属于一台设备并引用一个模板版本 |
| `inspection_task` | 保存一次具体点检待办及状态 | 属于一台设备；可关联计划；引用模板版本 |
| `inspection_record` | 保存一次提交的点检记录主信息 | 一般与一个任务一对一；属于一台设备和一个检查人员 |
| `inspection_result` | 保存点检记录下每个检查项目的实际结果 | 属于一条点检记录；引用检查项目并保存内容快照 |
| `abnormal_record` | 保存点检或日常巡查发现的异常 | 关联设备；可关联点检记录和具体检查结果 |
| `hazard_record` | 保存 EHS 确认后的正式隐患 | 第一版来源于一条异常；拥有整改和复查记录 |
| `rectification_record` | 保存每次整改措施、证据和提交信息 | 属于一条隐患；由设备责任人提交 |
| `review_record` | 保存每次 EHS 复查结果 | 属于一条隐患；可关联本次被复查的整改记录 |
| `attachment` | 保存未来附件元数据和存储路径 | 可关联点检明细、异常、整改或复查记录 |
| `operation_log` | 保存关键配置和状态变更审计信息 | 记录对象类型、对象 ID、操作者、前后值和时间 |

### 11.2 核心关系

```text
equipment 1 ── N inspection_plan
equipment 1 ── N inspection_task
inspection_template 1 ── N inspection_item
inspection_plan N ── 1 inspection_template
inspection_plan 1 ── N inspection_task
inspection_task N ── 1 equipment
inspection_task 1 ── 0..1 inspection_record
inspection_record 1 ── N inspection_result
inspection_record 1 ── 0..N abnormal_record
inspection_result 1 ── 0..N abnormal_record
abnormal_record 1 ── 0..1 hazard_record
hazard_record 1 ── N rectification_record
hazard_record 1 ── N review_record
```

### 11.3 为 Supabase 开发预留的原则

- 核心主键优先使用 UUID，业务编号另设唯一字段，不把可读编号作为外键。
- 任务生成时保存模板版本或检查项目快照，确保历史记录不可因模板修改而漂移。
- 状态变更使用受控服务逻辑并写入操作日志，不能只依赖前端更新字段。
- 时间统一保存带时区的时间戳，计划日期可单独使用日期字段；页面按用户时区展示。
- 附件表只保存元数据和受控存储路径，未来由 Supabase Storage 管理文件。
- 使用外键、非空约束、唯一约束和检查约束保证基础完整性。
- 使用 Supabase Row Level Security 按角色、执行人员和设备责任人限制行级访问；服务端仍需复核关键业务权限。
- 点检记录、异常审核、整改和复查采用留痕更正，不进行无审计的物理删除。

## 12. 第一版验收口径

- 能从一台在用设备及其点检设置生成或展示一条点检任务；
- 点检执行人员可以逐项填写并提交完整点检记录；
- 全部项目正常时，任务完成且不产生异常；
- 任一项目异常时，可以同时形成待确认异常，但不会自动形成隐患；
- EHS 管理员可以把异常判定为一般异常、驳回或确认形成隐患；
- 确认形成隐患后，可以完成分派、整改、复查和关闭演示；
- 设备详情能够追溯点检任务、点检记录、异常、隐患、整改和复查关系；
- 不同角色只能查看和执行其权限范围内的操作。

## 13. 后续开发前需要确认的规则

- 常规点检任务的执行人员第一版是直接指定，还是按设备责任部门维护默认点检人员；
- 特殊补录是否需要额外审批，还是由 EHS 管理员补录并完整记录代录信息即可；
- 点检任务提交后如发现录入错误，是采用“更正记录”还是由 EHS 管理员作废后重建任务；
- 同一任务是否允许多名执行人员协作。第一版建议只指定一名主执行人员。
